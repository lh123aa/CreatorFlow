## 三、更新流程

### 3.1 标准更新流程

```
┌─────────────────────────────────────────────────────────┐
│                    更新流程图                            │
└─────────────────────────────────────────────────────────┘

Step 1: 识别更新需求
    │
    ├─→ 定期检查（每月/每季度）
    │
    ├─→ 收到反馈
    │
    └─→ 发现过时内容
            │
            ▼
Step 2: 信息收集与验证
    │
    ├─→ 搜索最新信息
    │   (使用 search_web 工具)
    │
    └─→ 交叉验证
            │
            ▼
Step 3: 内容更新
    │
    ├─→ 修改文档内容
    │
    ├─→ 标注更新日期和版本
    │
    └─→ 保存文档
            │
            ▼
Step 4: 索引同步
    │
    ├─→ 更新总索引
    │
    ├─→ 更新相关链接
    │
    └─→ 验证可访问性
            │
            ▼
Step 5: 完成记录
    │
    └─→ 记录更新日志
            │
            ▼
        ✅ 完成
```

### 3.2 快速更新清单

**当你发现某个内容过时或需要更新时：**

```
□ 1. 标记需要更新的内容
```

## 五、版本管理规范

### 5.1 版本号规则

```
V主版本.次版本.修订版本

示例：V59.0
├── 主版本(59): 重大框架变更
├── 次版本(0): 常规更新
└── 修订版本: 小的修正

更新规则：
├── 修订版本：错别字、格式调整
├── 次版本：内容更新、补充新信息
└── 主版本：框架重构、重大方向调整
```

### 5.2 文档头部标注

每次更新时，请在文档头部更新以下信息：

```markdown

> **更新日期**：2026年6月1日
> **上次更新**：2026年5月3日
> **更新内容**：补充TikTok新变现政策
```

## 七、新增内容指南

### 7.1 新增来源

| 来源 | 说明 | 优先级 |
|------|------|--------|
| 实践反馈 | 使用中遇到的新问题 | 🔴 高 |
| 行业变化 | 新平台、新功能 | 🔴 高 |
| 用户需求 | 读者反馈的需求 | 🟡 中 |
| 趋势预判 | 未来可能出现的内容 | 🟢 低 |

### 7.2 新增流程

```
1. 识别需求
   └─→ 来源：反馈、趋势、空白
   
2. 评估优先级
   └─→ 标准：实用性、独特性、时效性
   
3. 规划位置
   └─→ 确定：主题分类、轮次位置
   
4. 撰写内容
   └─→ 遵循：现有结构和风格
   
5. 整合索引
   └─→ 更新：总目录、相关索引
   
6. 验证完整
   └─→ 检查：链接、可访问性
```

## 十、常见问题

### Q1: 什么时候需要更新版本号？

```
- 主版本(V59→V60)：重大框架调整
- 次版本(V59.0→V59.1)：常规内容更新
- 修订版本(V59.1→V59.1.1)：小的修正
```

### Q2: 如果信息冲突怎么办？

```
1. 优先采信官方来源
2. 多个来源交叉验证
3. 标注信息来源和日期
4. 说明"仅供参考"
```

### Q3: 某些内容无法验证怎么办？

```
1. 标注"信息待验证"
2. 给出验证方法
3. 说明不确定性
4. 提供替代方案
```

### Q4: 发现过时内容怎么办？

```
1. 立即标记"过时"
2. 搜索最新信息
3. 更新内容
4. 同步索引
5. 记录更新时间
```
