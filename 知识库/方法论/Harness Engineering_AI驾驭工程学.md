# Harness Engineering：AI驾驭工程学

> 来源：视频文案
> 整理时间：2026-04-24
> 核心逻辑：**人定规则、AI执行、人做校验**

---

## 一、核心定位

**定义**：AI时代的新工程范式，"驾驭AI能力的工程方法论"

**本质**：AI协作工程学

**核心对比**：

| 传统开发 | Harness Engineering |
|---------|---------------------|
| 人写代码 → 机器执行 | 人定目标 → AI出方案 → 人审核 → AI落地 |
| 人主导、AI辅助 | 人定规则、AI执行、人做校验 |

---

## 二、核心原则

### 原则1：目标先于工具

**执行顺序**：
1. 先明确"要解决什么问题、达成什么结果"
2. 再选择适配的AI工具（Claude、GPT、Copilot等）

**避坑**：禁止"盲目跟风用AI"，避免需求模糊导致返工

**核心动作**：用"目标拆解"替代"工具堆砌"

### 原则2：流程可复用

**要求**：将人机协作步骤标准化、模板化

**标准流程模板**：
```
需求拆解 → AI方案生成 → 人工校验 → AI优化迭代 → 落地复盘
```

**核心价值**：
- 新人可直接套用，无需从零摸索
- 保证协作效率与结果一致性

### 原则3：结果可验证

**核心机制**：针对AI输出的"不确定性"，建立双重校验机制

**校验标准**：
- 通用标准：明确AI输出的合格线
- 分层校验：非关键模块自动化校验，关键模块人工审核

**核心逻辑**：校验不是"挑错"，而是给AI定规则、喂反馈，形成"校验-优化"闭环

## 三、四大核心能力

### 能力1：需求拆解能力（人类核心价值）

**核心动作**：将模糊需求转化为AI可精准执行的颗粒化指令

**示例对比**：

| 模糊需求 | 拆解后指令 |
|---------|-----------|
| "做一个高效的用户管理系统" | "用户注册模块支持手机号/邮箱双验证；密码需含大小写+数字+特殊字符；兼容Web/移动端；权限分管理员/普通用户两级；数据加密存储" |

**核心本质**：人类从"执行者"升级为"问题定义者"

### 能力2：提示词工程能力

**不是"写复杂Prompt"，而是设计可复用的提示词模板**

**模板核心要素**：
- 角色定位
- 需求边界
- 输出格式
- 校验标准

**示例模板**：
```
角色："资深后端开发工程师，熟悉Python 3.9+与PEP8规范"
需求："编写用户注册模块代码，包含手机号验证、密码加密、权限分配功能"
输出要求："代码需完整注释，兼容Windows/Linux系统，附简单使用说明"
```

**核心价值**：一次模板化，AI长期适配

### 能力3：工具整合能力

**核心要求**：将AI工具与现有工作流无缝对接，形成闭环

**典型场景**：

| 场景 | 闭环流程 |
|-----|---------|
| 代码类 | AI生成代码 → 自动同步GitHub → 自动化测试 → AI修复报错 |
| 设计类 | AI出设计稿 → 自动导出格式 → 同步项目管理工具 → 设计师优化 |

### 能力4：风险控制能力

**核心风险**：AI输出的不确定性（代码漏洞、信息错误、合规问题）

**防控措施**：
- 规则前置：定义AI输出的"红线标准"
- 分层防护：核心模块人工审核，辅助模块自动化校验
- 容错机制：设置AI输出异常时的"兜底流程"

## 四、应用场景

| 场景 | 流程 |
|-----|------|
| 软件开发 | 需求拆解 → AI写代码 → 自动测试 → AI修复 → 人工审核上线 |
| 产品设计 | PM输出需求 → AI生成原型 → 设计师优化 → AI适配多端格式 |
| 运营工作 | 明确活动目标 → AI生成方案/文案 → 人工调整 → AI批量生成素材 |
| 商务场景 | 撰写邮件/合同 → AI初版 → 人工合规校验 → AI优化措辞 |

---

## 五、核心价值

1. **效率提升**：替代80%重复、机械、低价值工作
2. **门槛降低**：非技术人员可完成原本需专业技能的工作
3. **规模化复制**：标准化流程快速推广
4. **风险可控**：通过校验与规则设计降低AI错误
