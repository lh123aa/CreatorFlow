## 二、Claude Design 是什么

### 定位
设计师的 Claude Code，功能强大但门槛高，被封装成人人可用的 Skill。

### 功能
- 输入需求，生成可交互的网页设计
- 输出可直接运行的代码链接
- 支持点击标签、切换主题、调整断点视图

### 设计逻辑
**与传统工具相反**：AI是主要生成者，人只需做好审核和判断。

## 四、提示词要点学习

### 1. 角色定位

| AI角色 | 用户角色 |
|-------|---------|
| 专家设计师 | 产品经理 |

**角色可动态切换**：动效设计师、UX设计师、Deck设计师等

### 2. 工作流

**流程**：理解需求 → 探索资源 → 制定计划 → 搭建结构 → 完成验证 → 极简总结

**关键原则**：
- 明确"何时提问、何时直接行动"
- 通过案例诠释提问的艺术
- 总结时"只说注意事项与下一步"，避免废话

### 3. 去 AI 味（核心！）

**禁止使用**：

| 禁止项 | 原因 |
|-------|------|
| 渐变背景 | AI味重 |
| Emoji图标 | 廉价感 |
| 左侧彩色卡片 | 套路化 |
| 烂大街字体（Inter、Roboto） | 无个性 |
| 无意义数据/图标 | 凑数 |

**推荐字体**：
- Plus Jakarta
- Sara
- Space Grotesk

### 4. 配色策略（三层防线）

| 优先级 | 策略 | 说明 |
|-------|------|------|
| 第一层 | 优先用品牌色 | 最安全 |
| 第二层 | 用OKLCH生成 | 解决HSL"感知不均匀"问题 |
| 第三层 | 禁止凭空造色 | 避免AI感 |

**为什么用OKLCH**：
> 传统HSL色彩空间"感知不均匀"，OKLCH能保证颜色搭配的和谐度。

### 5. 内容原则

> **每个元素需"证明自己为什么该在那"**

**提倡大胆留白**：
> 一个大胆的留白比十个凑数的板块更有表现力。

### 6. 验证机制

**开发完成后**：fork一个独立的子agent对网页做全面检查

**为什么**：避免单个agent自我确认的偏差

### 制作背景

- 基于泄露的提示词制作了该Skill

## 六、测试对比

**测试环境**：cursor + Claude Opus 4.7

### 案例一：太空探索博物馆网页

| 版本 | 评价 |
|-----|------|
| 没用Skill | 配色青紫粉渐变、字体老套、布局教科书式卡片，缺乏视觉创意 |
| 用了Skill | 配色基于OKLCH、字体有特点、布局非传统卡片、动画舒服有创意，像资深设计师作品 |

### 案例二：独立摄影师个人网站

| 版本 | 评价 |
|-----|------|
| 没用Skill | 深色背景、霓虹发光、半透明卡片、AI感文案，缺乏摄影师"慢、真"风格 |
| 用了Skill | 虚构北欧摄影师形象、设计完整视觉风格、像高端摄影画册 |

### 测试总结

> 没用Skill版本本身已不错（Opus 4.7生成质量高于多数程序员手写），但用了Skill后：
> - 85分 → 95分
> - 能用 → 好看
> - 完整 → 精致
> - 合格 → 有风格

**原因**：提示词中多条规则的量变积累。

## 七、对小红书创作Skill的借鉴

### 提示词优化方向

**1. 增加禁止清单**

| 禁止项 | 替代方案 |
|-------|---------|
| "让你秒懂""必看"等标题党 | 具体痛点+场景 |
| 表情符号堆砌 | 精简emoji，最多2-3个 |
| "很多人不知道"开头 | 直接说场景痛点 |
| 空洞鸡汤 | 具体行动点 |

**2. 验证机制**

生成内容后，fork一个检查agent：
- 检查是否有"AI味"表达
- 检查行动点是否具体
- 检查案例是否真实

**3. 内容原则**

> 每句话要"证明自己为什么该在那"

删除凑数的段落，保留有信息量的内容。

### 具体可加的规则

```
禁止：
- "让你秒懂""必看""建议收藏"等标题党
- "很多人不知道""99%的人不知道"开头
- 表情符号超过3个
- 空洞鸡汤（"相信自己""坚持就是胜利"）
- 没有具体行动点的总结

推荐：
- 开头直接描述痛点场景
- 中间提供内行细节解决方案
- 结尾给出具体下一步行动
```
