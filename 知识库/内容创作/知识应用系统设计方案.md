# 自媒体知识应用系统设计方案

## 一、问题诊断

### 当前痛点
1. **学用分离**：每天学习积累的知识分散在5个模板库文件，写文案时靠"想起来"去查
2. **Token浪费**：每次创作都读取所有模板库，上下文冗余
3. **触发不稳定**：Skill依赖平台自动识别，账号处理案例显示触发失败
4. **无强制机制**：没有流程确保学过的知识一定被应用

### 核心矛盾
> 知识存了 ≠ 每次都用
> 全量加载 = Token浪费
> 按需加载 = 触发不稳定

---

## 二、解决方案：三层索引系统

### 设计理念
借鉴RAG检索增强生成 + Skill三层架构的思想：
- **不预加载所有知识**
- **建立轻量级索引目录**
- **通过任务分析精确匹配需要的知识模块**
- **只加载相关模块**

### 架构图

```
┌─────────────────────────────────────────────────────────────┐
│                    第一层：索引目录（始终加载）                  │
│  存储位置：MEMORY.md 或 专用索引文件                           │
│  内容：知识模块清单 + 关键词映射 + 触发规则                      │
│  Token消耗：约500 tokens                                     │
└─────────────────────────────────────────────────────────────┘
                              ↓ 任务分析后匹配
┌─────────────────────────────────────────────────────────────┐
│                  第二层：知识模块（按需加载）                    │
│  存储位置：./知识库/各规范文件                                  │
│  内容：具体的公式、模板、案例                                   │
│  Token消耗：每次约1000-3000 tokens                            │
└─────────────────────────────────────────────────────────────┘
                              ↓ 创作时引用
┌─────────────────────────────────────────────────────────────┐
│                  第三层：参考资源（可选加载）                    │
│  存储位置：./知识库/案例库、素材库                               │
│  内容：优秀案例、素材模板                                       │
│  Token消耗：按需                                               │
└─────────────────────────────────────────────────────────────┘
```

## 三、具体实现

### 3.1 第一层：索引目录

**存储位置**：`./知识库/自媒体创作规范/知识索引.md`

**内容结构**：
```markdown
# 自媒体创作知识索引

## 快速检索表

| 任务类型 | 需要的知识模块 | 文件路径 |
|---------|--------------|---------|
| 写小红书图文 | 选题+标题+正文+封面设计 | 选题模板库、标题模板库、正文模板库、设计模板库 |
| 写抖音脚本 | 选题+标题+正文 | 选题模板库、标题模板库、正文模板库 |
| 写公众号文章 | 正文模板库 | 正文模板库 |
| 做视频封面 | 封面设计 | 设计模板库 |

## 知识模块清单

### 1. 选题模板库
- **路径**：`./知识库/选题规范/选题模板库.md`
- **核心内容**：7种选题类型公式
- **触发关键词**：选题、确定主题、写什么内容
- **快速公式**：
  - 痛点型：[具体痛点] + [情绪词] + [解决方案预告]
  - 信息差型：[反常识观点] + [具体数据] + [新方法论]
  - 真实失败逆袭型：[具体失败] + [真实情感] + [行动转变] + [可验证结果]

### 2. 标题模板库
- **路径**：`./知识库/标题规范/标题模板库.md`
- **核心内容**：9种标题类型公式
- **触发关键词**：标题、封面文字、标题怎么写
- **快速公式**：
  - 数字型：[数字] + [时间/结果] + [利益点]
  - 痛点型：[具体痛点] + [情绪词] + [反转/解决方案]
  - 情绪化反转型：[矛盾体] + [反问] + [情绪词] + [悬念]

### 3. 正文模板库
- **路径**：`./知识库/正文规范/正文模板库.md`
- **核心内容**：9种正文结构模板
- **触发关键词**：正文、内容、文章结构、怎么写
- **快速公式**：
  - 爆款结构：痛点引入(1-2句) → 价值输出(3-4句) → 细节拆解 → 引导互动(1句)
  - AIDA：注意 → 兴趣 → 欲望 → 行动

### 4. 设计模板库
- **路径**：`./知识库/设计规范/设计模板库.md`
- **核心内容**：封面设计规范、配色方案
- **触发关键词**：封面、配图、设计、图片
- **核心要点**：
  - 文字控制在5-8字内
  - 字体颜色用1-2种对比色
  - 莫兰迪色系 + 亮色点缀

### 5. 钩子文案规范
- **路径**：`./知识库/自媒体创作规范/钩子文案创作规范.md`
- **核心内容**：7种钩子公式
- **触发关键词**：钩子、开头、吸引眼球
- **核心公式**：钩子 + 价值/痛点 + 触发词
```

### 3.2 MEMORY.md 关键信息（始终可检索）

在 `MEMORY.md` 中添加知识索引的精简版：

```markdown
## 自媒体创作知识索引

创作任务时，先判断需要哪些模块，再精确读取：

| 任务类型 | 读取模块 |
|---------|---------|
| 小红书图文 | 选题+标题+正文+设计 |
| 抖音脚本 | 选题+标题+正文 |
| 视频封面 | 设计模板库 |

**核心公式速查**：
- 选题：痛点型/信息差型/逆袭型
- 标题：数字型/痛点型/情绪化反转
- 正文：痛点引入→价值输出→细节拆解→引导互动
- 封面：5-8字、1-2种对比色

**详细内容路径**：`./知识库/自媒体创作规范/知识索引.md`
```

### 3.3 创作流程标准化

```
用户提出创作任务
       ↓
【步骤1】分析任务类型
  - 是图文？视频？文章？
  - 平台是什么？（小红书/抖音/公众号）
       ↓
【步骤2】查索引目录
  - 读取 MEMORY.md 或 知识索引.md
  - 确定需要哪些知识模块
       ↓
【步骤3】精确加载知识模块
  - 只读取相关的模板库文件
  - 不全量加载
       ↓
【步骤4】应用知识创作
  - 按公式套用
  - 逐项检查清单
       ↓
【步骤5】输出成果
```

## 四、Skill触发稳定性方案

### 问题根源
平台Skill触发依赖关键词匹配，容易失败。

### 解决方案：双重保障

#### 方案A：显式调用（推荐）
用户明确指定使用某个Skill，如：
- "用小红书创作skill帮我写一篇笔记"
- "用账单处理skill处理这个账单"

#### 方案B：MEMORY.md兜底
即使Skill触发失败，memory_search也能搜到相关信息：
- MEMORY.md中记录核心流程
- 附上Skill文件路径，手动加载

#### 方案C：索引文件自动读取
在索引文件中记录触发规则，每次创作前主动读取索引文件判断是否需要加载某个Skill。

## 七、关键原则

1. **索引精简**：索引文件控制在500 tokens内，确保能快速读取
2. **模块化**：每个知识模块独立，可单独加载
3. **强制流程**：创作前必须读索引，不允许跳过
4. **持续迭代**：每次创作后检查哪些知识没用上，优化索引
