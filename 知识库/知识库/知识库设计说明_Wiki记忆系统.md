# Wiki记忆系统设计说明

## 一、我现在的记忆系统 = 堆积仓库

```
对话发生 → 被动写入MEMORY.md → 需要时语义搜索
```

### 存在的问题

**1. 信息是死的**
- 你跟我说"litellm投毒事件"，我写入MEMORY.md
- 下次你问"供应链攻击"，我语义搜索可能找到，也可能找不到
- 信息之间没有关联，像孤岛

**2. 没有加工过程**
- 原始对话直接存进去
- 没有提取概念、实体、关联
- 每次检索都要重新理解一遍

**3. 只进不出，越堆越乱**
- 东西越来越多，但没有整理
- 过时的信息没有被标记
- 冲突的信息没有被发现

**类比**：像一个**乱糟糟的仓库**，东西往里一扔，找的时候全靠翻。

---

## 二、Wiki记忆系统 = 有机生长的知识库

```
原始资料 → ingest编译 → 结构化笔记 → 索引+关联 → 持续维护
```

### 解决的核心问题

#### 问题1：信息孤岛 → 概念关联

**现在**：
- litellm投毒 → 存入MEMORY.md
- 一人公司商业模式 → 存入另一个文件
- 两者其实有关联（供应链信任成本），但没人知道

**Wiki系统**：
- ingest时自动提取"供应链安全"、"信任成本"等概念
- 建立双向链接：`[[供应链安全]]` ← → `[[一人公司商业模式]]`
- 你问任何一个话题，我能顺藤摸瓜找到关联

#### 问题2：每次都重新理解 → 知识资产化

**现在**：
- 你问我"最近在研究什么"
- 我重新读MEMORY.md，重新理解，重新总结

**Wiki系统**：
- 已经编译好了项目笔记、概念笔记
- 我直接读结构化的笔记
- 理解一次，反复使用

**类比**：租房 vs 买房
- RAG（语义搜索）= 租房，每次都要重新装修
- Wiki = 买房，装修一次永久使用

#### 问题3：越堆越乱 → 持续维护

**现在**：
- MEMORY.md越来越大，没人管
- 里面的信息可能过时、冲突
- 没有"清理"机制

**Wiki系统**：
- lint（巡检）定期扫描
- 发现死链（引用的文件不存在）
- 发现孤立页面（没人引用的笔记）
- 发现知识冲突（同一个概念在不同笔记里说法矛盾）

#### 问题4：不知道我知道什么 → 索引导航

**现在**：
- 你问我"你记得什么"
- 我只能说"我有很多记忆，你问具体的"

**Wiki系统**：
- 有index.md索引文件
- 清晰列出：所有项目、所有概念、所有实体
- 一眼看懂知识库全貌

## 三、具体案例对比

**场景**：研究litellm投毒事件

### 现在的处理方式
```
对话内容 → 写入MEMORY.md（可能只是一句话提到）
          → 下次你问，语义搜索可能找到，也可能漏掉
```

### Wiki的处理方式
```
对话内容 → ingest编译：
  ├─ 提取实体：
  │    ├─ [[litellm]]（Python库）
  │    ├─ [[TeamPCP]]（攻击者）
  │    └─ [[Karpathy]]（评论者）
  │
  ├─ 提取概念：
  │    ├─ [[供应链攻击]]
  │    ├─ [[信任链]]
  │    └─ [[依赖安全]]
  │
  ├─ 关联已有笔记：
  │    ├─ [[一人公司商业模式]] ← 关联点：信任成本
  │    └─ [[AI工具使用]] ← 关联点：开源依赖风险
  │
  └─ 更新索引和变更日志
```

**下次你问**：
- "供应链攻击有什么案例？" → 我直接从`[[供应链攻击]]`笔记找到litellm案例
- "开源工具有什么风险？" → 我从`[[依赖安全]]`笔记找到相关讨论
- "我最近研究了什么安全相关的内容？" → 我查索引，列出所有安全相关笔记

## 四、核心价值

### 对一人公司的价值
- 你持续学习一个领域 → 知识库自动积累
- 知识库本身就是可变现的资产
- 可以导出成课程、电子书、咨询服务

### 对个人效率的价值
- 不用重复理解同一个问题
- 知识之间自动关联，产生新洞察
- 定期巡检，发现知识盲区和冲突

## 五、一句话总结

**Wiki记忆系统 = 把"堆积的仓库"变成"有机生长的知识花园"**

- 原始资料是"种子"
- ingest是"播种+培育"
- 笔记是"长大的树"
- 索引是"花园地图"
- lint是"园丁维护"
- 关联链接是"树木之间的生态关系"

**说人话**：
- 现在：我的记忆是"杂乱的书堆"
- 之后：我的记忆是"有目录、有索引、有互相关联的图书馆"
