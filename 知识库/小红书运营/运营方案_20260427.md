## 一、账号定位重设计

### 1.1 人设转型

| 维度 | 转型前 | 转型后 |
|------|--------|--------|
| **身份标签** | AI工具博主 | 35岁转型者 + AI创业者 |
| **核心叙事** | 工具推荐合集 | 100天真实挑战记录 |
| **内容调性** | 工具罗列 | 踩坑复盘 + 开源实战 |
| **差异化** | 信息差收割 | 真实、可信、有温度 |

### 1.2 账号定位陈述

**一句话定位**：
> 一个35岁技术人的100天AI创业挑战，真实记录从0到1做开源项目的全过程

**账号价值主张**：
- 🎯 **真实可信**：不夸大、不虚标，每日真实数据复盘
- 🔧 **实战导向**：每一个项目都有GitHub可查的源码
- 💪 **共鸣传递**：35岁转型的焦虑与突破，与目标用户同频
- 📈 **可复制性**：方法论可迁移，工具可复用

### 1.3 目标用户画像

| 用户类型 | 核心痛点 | 内容期待 |
|----------|----------|----------|
| 35岁+技术人 | 职业焦虑、转型迷茫 | 转型路径、真实案例 |
| AI开发者 | 寻找趁手工具 | 工具实测、开源项目 |
| 技术创业者 | 项目冷启动 | 增长策略、项目推广 |
| 副业探索者 | 变现路径模糊 | 可落地的变现方法 |

```
                    │   故事共鸣类    │  ← 涨粉主力
                    │  (占40%权重)    │
                    └────────┬────────┘

        ┌────────────────────┼────────────────────┐
        │                    │                    │
        ▼                    ▼                    ▼
┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│   数据复盘类   │    │   工具实测类   │    │  开源项目类    │

│ 涨粉原因分析   │    │ 替代方案对比   │    │ 使用教程       │
└───────────────┘    └───────────────┘    └───────────────┘
```

### 2.2 发布频率调整

| 阶段 | 频率 | 原因 |
|------|------|------|
| 之前 | 日更 | 质量参差、数据难看 |
| 现在 | **每周3篇** | 保障内容质量、留出复盘时间 |
| 后续 | 根据数据反馈动态调整 |  |

**发布节奏**：
- 周二、周四、周日 20:00 发布
- 留出1天间隔用于数据观察

### 2.3 标题公式

**核心公式**：
```
[人群标签] + [进度/阶段] + [数字/情绪钩子]
```

**标题模板库**：

| 场景 | 模板 | 示例 |
|------|------|------|
| 数据复盘 | 「X天真实数据，X个关键发现」 | 「Day 7真实复盘：3441曝光为何涨粉为0？」 |
| 故事共鸣 | 「[年龄]岁[状态]，我决定[行动]」 | 「35岁被裁，我用100天做了个开源工具」 |
| 工具测评 | 「[痛点]，我用[工具]解决了」 | 「写代码太慢？这个MCP插件让我效率翻倍」 |
| 项目推广 | 「[成果]，开源项目复盘」 | 「30天做出GitHub 500 Star的项目，我做了什么」 |
| 干货输出 | 「[数字]个[主题]，第X条最关键」 | 「做AI创业必须知道的5件事，第3条最难」 |

### 2.4 AI治理合规指南

**四类高风险内容（禁止）**：
1. ❌ 批量生成无差异内容（同一模板换词多次发布）
2. ❌ 虚假数据/效果夸大（"一天涨粉1000"类标题）
3. ❌ 未授权素材（他人项目截图无说明）
4. ❌ 低质内容（水内容、无信息增量）

**安全内容原则**：
- ✅ 真实数据：所有数据必须有来源、可验证
- ✅ 个人经历：标注"个人经验，效果因人而异"
- ✅ 原创内容：项目截图、代码演示均为本人成果
- ✅ 有价值输出：每篇笔记至少1个可操作的干货点

## 三、Forge项目推广方案

### 3.1 融入100天故事线

```
Day 7-9        Day 10-14       Day 15-21       Day 22+
│              │               │               │
▼              ▼               ▼               ▼
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 发现痛点  │ → │ 开发Forge │ → │ 项目上线  │ → │ 迭代优化  │
│ 数据反思  │   │ 公开开发  │   │ GitHub 500+ │ │ 用户反馈  │
└──────────┘   └──────────┘   └──────────┘   └──────────┘
     │              │               │               │
     ▼              ▼               ▼               ▼
  故事共鸣      过程展示         成果展示        持续运营
```

### 3.2 选题角度矩阵

| 角度 | 内容形式 | 目标效果 | 示例标题 |
|------|----------|----------|----------|
| **技术向** | 代码演示截图 | 建立专业信任 | 「用MCP协议做了个代码生成插件，核心源码公开」 |
| **故事向** | 开发过程Vlog | 引发情感共鸣 | 「连续肝了7天，我的第一个GitHub开源项目上线了」 |
| **效果向** | 数据截图 | 展示实际价值 | 「用这个工具，代码生成效率提升300%（附对比）」 |
| **教程向** | Step-by-step | 实用价值 | 「5分钟集成MCP插件，手把手教程」 |

### 3.3 合规推广方式

**✅ 可以做的**：
1. 真实使用场景演示（录制实际操作的屏幕录制）
2. 开源项目冷启动的真实数据（Star数、Issue数）
3. 项目开发过程中的踩坑与解决
4. 个人使用体验的客观描述
5. GitHub项目地址的自然植入

**❌ 不能做的**：
1. 夸大Star数或用户量（"10000+开发者使用"）
2. 伪造使用效果（"用了这个工具月入10万"）
3. 批量发布相似推广内容
4. 使用AI批量生成推广文案

### 3.4 双重目标策略

| 目标 | 策略 | 协同点 |
|------|------|--------|
| **涨粉** | 故事向内容吸引关注 | 关注人 → 成为粉丝 |
| **GitHub Star** | 技术向内容促进转化 | 粉丝 → Fork/Star |

**转化路径**：
```
小红书曝光 → 笔记吸引 → 关注账号
                              │
                              ▼
GitHub链接/项目名 → 点击访问 → 了解项目 → Star/Fork
                              │
                              ▼
                         持续关注项目 → 成为用户
```
