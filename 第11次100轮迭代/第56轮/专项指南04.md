# API对接与自定义工作流

## 一、API基础知识入门

### 1.1 什么是API？

API（Application Programming Interface，应用程序编程接口）是不同软件之间通信的桥梁。对于创作者来说，理解API是实现高级自动化的关键。

**类比理解**

```
想象你在餐厅点餐：
- 你（用户）不需要知道厨房怎么工作
- 你只需要向服务员（API）点菜
- 服务员把你的请求（API调用）传给厨房
- 厨房准备好食物后，服务员端给你（响应）

API的工作方式类似：
- 你（应用）不需要知道另一个系统怎么工作
- 你通过API发送请求
- 对方系统处理后返回结果
- 你使用返回的数据
```

**API在创作者工作中的应用**

```
没有API：
手动复制数据 → 粘贴到表格 → 手动计算 → 发送邮件

有API：
系统A（新数据）→ API调用 → 系统B（处理）→ API响应 → 系统A（更新状态）
```

### 1.2 REST API核心概念

**URL结构**

```
https://api.example.com/v1/users/123/posts

组成部分：
- https://api.example.com - API基础URL
- /v1 - API版本
- /users - 资源路径
- /123 - 特定资源ID
- /posts - 子资源

HTTP方法：
GET    - 获取数据
POST   - 创建新数据
PUT    - 更新数据
DELETE - 删除数据
```

**请求和响应格式**

```
API请求示例：
GET https://api.instagram.com/v1/users/123/media/recent
Headers:
  Authorization: Bearer ACCESS_TOKEN
  Content-Type: application/json

API响应示例：
{
  "data": [
    {
      "id": "media_123",
      "type": "image",
      "url": "https://...",
      "likes": 150,
      "comments": 25
    }
  ],
  "pagination": {
    "next_url": "https://..."
  }
}
```

### 1.3 认证方式

**1. API Key认证**

最简单的方式，直接在请求中传递密钥：

```
Header: X-API-Key: your_api_key_here
或
Query参数: ?api_key=your_api_key_here
```

适用场景：
- 服务器之间的安全通信
- 简单的API访问

**2. OAuth 2.0认证**

更安全的授权方式，用户授权后获得访问令牌：

```
流程：
1. 用户点击"授权"
2. 重定向到授权页面
3. 用户同意授权
4. 获取授权码
5. 用授权码换取Access Token
6. 使用Access Token访问API
```

适用场景：
- 需要访问用户私有数据
- 需要用户授权的场景

**3. Bearer Token**

OAuth授权后获得的令牌：

```
Header: Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### 3.3 自定义函数编写

**Make中的JavaScript函数**

```javascript
// 示例1：计算互动率
function calculateEngagementRate(likes, comments, views) {
    if (views === 0) return 0;
    const engagement = ((likes + comments) / views) * 100;
    return Math.round(engagement * 100) / 100;
}

// 示例2：格式化日期
function formatDate(dateString) {
    const date = new Date(dateString);
    const options = { year: 'numeric', month: 'long', day: 'numeric' };
    return date.toLocaleDateString('en-US', options);
}

// 示例3：从标题提取关键词
function extractKeywords(title) {
    const stopWords = ['the', 'a', 'an', 'is', 'are', 'in', 'on', 'at'];
    const words = title.toLowerCase()
        .replace(/[^\w\s]/g, '')
        .split(' ')
        .filter(word => word.length > 2 && !stopWords.includes(word));
    return [...new Set(words)];
}

// 示例4：生成SEO友好的slug
function generateSlug(title) {
    return title
        .toLowerCase()
        .replace(/[^\w\s-]/g, '')
        .replace(/\s+/g, '-')
        .replace(/-+/g, '-')
        .trim();
}

// 示例5：计算预测观看
function predictFinalViews(earlyViews, hoursSinceUpload, targetHours = 48) {
    if (hoursSinceUpload === 0) return 0;
    const hourlyRate = earlyViews / hoursSinceUpload;
    const predictedViews = hourlyRate * targetHours;
    return Math.round(predictedViews);
}
```

### 3.4 错误处理与重试

**错误处理配置**

```
在Make中添加错误处理：

1. 添加Error Handler模块
2. 选择错误处理方式：
   - Resume: 继续执行下一个模块
   - Break: 停止场景
   - Ignore: 忽略错误继续
   - Return: 返回自定义错误

配置示例：

步骤1: HTTP请求
  └─ 错误 → 步骤2

步骤2: Error Handler
  ├─ 如果是429（限流）→ 等待1分钟 → Resume
  ├─ 如果是401（认证）→ 发送告警 → Break
  ├─ 如果是500（服务器）→ 等待2分钟，尝试3次 → Break
  └─ 其他错误 → 记录日志 → Break
```

**重试配置**

```
HTTP模块重试设置：

Retry configuration:
- Maximum attempts: 3
- Retry interval: 1 minute
- Timeout: 30 seconds

Backoff策略：
- Simple: 固定间隔重试
- Exponential: 间隔时间指数增长
```

## 五、API安全与最佳实践

### 5.1 API安全原则

**保护你的API密钥**

```
安全实践：
1. 永远不要在前端代码中暴露API密钥
2. 使用环境变量存储密钥
3. 定期轮换API密钥
4. 为不同的应用使用不同的密钥
5. 设置API密钥的使用限制

在Make/Zapier中：
- 使用"Encrypted"存储方式
- 不要在日志中暴露敏感数据
- 设置适当的作用域
```

**请求频率控制**

```
API限制类型：
1. Rate Limit（速率限制）
   - 每分钟/每小时/每天请求数上限
   - 超出返回429错误

2. 配额限制
   - 每月免费/付费配额
   - 需要升级获取更多配额

应对策略：
1. 添加延迟（Delay模块）
2. 实现重试机制
3. 使用缓存减少重复请求
4. 批量请求（如果API支持）
```

### 5.2 数据隐私合规

**中东地区数据合规**

```
GCC数据法规考虑：
1. 沙特阿拉伯PDPL（个人数据保护法）
2. 阿联酋数据保护法规
3. 卡塔尔数据保护法

创作者合规要点：
- 收集用户数据需明确告知
- 征得用户同意
- 妥善保管数据
- 不向境外传输敏感数据（部分国家）
- 提供数据删除选项
```

**数据处理建议**

```
收集最少原则：
- 只收集必要的数据
- 定期清理不必要的数据
- 加密敏感数据

存储安全：
- 使用加密存储
- 限制访问权限
- 定期备份
- 遵守数据保留政策
```

### 5.3 性能优化

**减少API调用**

```
优化策略：
1. 缓存响应
   - 缓存不常变化的数据
   - 设置合理的缓存时间

2. 批量请求
   - 一次获取多条数据
   - 减少请求次数

3. 选择性字段
   - 只获取需要的字段
   - 减少响应大小

4. 轮询优化
   - 不要过于频繁轮询
   - 使用Webhook替代轮询（如可用）
```

**响应处理优化**

```
示例：YouTube数据获取

❌ 低效：获取所有数据后再处理
1. 获取频道数据
2. 获取播放列表
3. 获取视频列表
4. 逐个获取统计
5. 处理所有数据

✅ 高效：批量获取+缓存
1. 获取频道数据
2. 获取播放列表
3. 批量获取视频数据（50个/请求）
4. 缓存响应
5. 从缓存读取处理
```

## 六、常见问题与排查

### 6.1 API调用常见错误

| 错误码 | 含义 | 解决方案 |
|--------|------|----------|
| 400 | 请求格式错误 | 检查参数和格式 |
| 401 | 未授权 | 检查API密钥/token |
| 403 | 权限不足 | 检查OAuth范围 |
| 404 | 资源不存在 | 检查ID是否正确 |
| 429 | 请求过多 | 添加延迟，使用缓存 |
| 500 | 服务器错误 | 稍后重试 |
| 503 | 服务不可用 | 检查服务状态 |
