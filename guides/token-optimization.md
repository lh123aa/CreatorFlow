# Token优化策略

## 一、问题分析

传统方式的Token消耗：
- 全量加载所有知识模块：~10000 tokens
- 每次创作重复加载：浪费严重
- 上下文冗余：影响生成质量

## 二、CreatorFlow优化策略

### 策略1：三层架构

| 层级 | 内容 | 加载时机 | Token消耗 |
|------|------|----------|----------|
| 索引层 | 模块清单+核心公式 | 始终可访问 | ~500 |
| 模块层 | 完整模板库 | 按需加载 | ~1000-2000/个 |
| 资源层 | 案例素材 | 可选加载 | 按需 |

### 策略2：主题分析前置

先分析再加载，避免无效读取：
```
主题分析（~100 tokens）→ 精确加载（~2000 tokens）
vs
全量加载（~10000 tokens）
```

### 策略3：核心公式记忆化

将最高频使用的公式写入长期记忆：
- 选题核心公式：5条
- 标题核心公式：5条
- 正文核心结构：2条
- 钩子核心公式：3条

总计~300 tokens，每次对话都能直接使用。

## 三、实际消耗对比

| 场景 | 传统方式 | CreatorFlow | 节省 |
|------|----------|-----------|------|
| 快速创作（标题+钩子） | ~10000 | ~1500 | 85% |
| 完整创作（全流程） | ~10000 | ~3500 | 65% |
| 日常学习更新 | ~10000 | ~2000 | 80% |

## 四、进阶优化

### 优化1：索引分级

```
一级索引（~200 tokens）：模块名称+路径
二级索引（~300 tokens）：核心公式速查
```

简单任务用一级索引，复杂任务用二级索引。

### 优化2：模块拆分

将大模块拆分为子模块：
```
正文模板库（~2000 tokens）
├── 爆款万能结构（~300 tokens）
├── AIDA结构（~200 tokens）
├── 情绪锚点式（~400 tokens）
└── ...
```

只加载需要的子模块。

### 优化3：缓存机制

对于频繁使用的模块，保持在上下文中：
- 标题模板库（高频）
- 钩子公式（高频）

低频模块按需加载后释放。

## 五、最佳实践

1. **创作前**：先做主题分析，确定最小加载集
2. **创作中**：优先使用记忆中的核心公式
3. **创作后**：检查哪些知识没用到，优化匹配逻辑
4. **迭代时**：持续精简模块，删除冗余内容

---

*Token优化是一个持续过程，在使用中不断迭代*
